# Easel localization pilot (PRD §8, SET-14)

**Deferred for the first build (user decision, 2026-10-30).** Keep the existing locale runtime and catalogs. Further string migration, additional locales, RTL acceptance and human translation review are later work, not first-build blockers. English is sufficient for first-build language acceptance; Canvas time-zone correctness remains a functional requirement.

The current pilot has 3,260 reviewed message keys per language in English, French and Arabic across the implemented student workflows. Translation quality and native language behavior are not fully accepted. `MIGRATION.md` and `checks/inventory.json` record heuristic candidates for later work; their counts are not confirmed untranslated-message totals. Historical implementation and acceptance notes below do not override this first-build deferral.

## Stable API

```tsx
import { useTranslation, formatNumber } from '@/i18n';
const { t, locale, catalog, direction } = useTranslation();
t('home.members', { count: 3 });
t('settings.signOut', { name: account.user.name });
formatNumber(1234.5); // effective Canvas locale, not a translated numeric string
```

Use the hook **inside every memoized rendering consumer**, and include `t` in dependencies for memoized strings. Outside React import `t`, `displayLocale`, `createTranslator` from `@/i18n/runtime`; for background work on a non-active account use `createTranslator(thatAccountsEffectiveLocale)`, never mutate the foreground store. Never translate server-authored content or use English source strings as keys.

React Compiler also memoizes calculations. A subscription alone does not make a call to a global formatter depend on locale/timezone. For persistent form values, construct formatters from explicit `locale` and `useDisplayTimeZone()` inputs; DateTimeRow demonstrates this. Calendar hour-axis labels use UTC clock carriers so a Canvas timezone cannot shift the abstract hour labels. Period swipes follow the viewing account's direction; their layout and gestures still need native verification.

`en.ts` is the literal typed source. `Catalog` requires identical keys and message shape in `fr.ts`/`ar.ts`. Placeholders are simple `{name}` slots; TypeScript infers required arguments. A plural entry has `other` and optional Intl cardinal categories (`zero`, `one`, `two`, `few`, `many`). Use numeric `count`; grammatical selection follows the catalog language while number formatting follows the full effective locale. No ICU, HTML, source-string replacement, gender parser or automatic translation. Untyped missing keys return the key; missing interpolation stays visible as `{name}`. A missing translation falls back to the English source and its grammar.

`canonicalLocale` validates/canonicalizes tags and Canvas aliases without selecting a fallback; `normalizeLocale` also checks Intl support and falls back to `en`. Valid supported locales retain region/numbering conventions even when the displayed catalog is English. UI direction follows the displayed catalog (Arabic RTL, English/French LTR), not untranslated Canvas content.

`CanvasLocaleSync` in `features/settings/locale.tsx` wraps the signed-in navigator. It reads the account-scoped profile's **effectiveLocale**, including the school default. Missing/invalid/uncached values start at English; there is no persisted global language preference. An account transition gates new screens until its formatters are initialized. Same-account language changes keep the navigator and drafts mounted. Boundary cleanup resets on sign-out and ignores cleanup from an obsolete account. Settings waits for the existing profile invalidation/refetch to obtain the server's effective locale after saving.

Date formatting remains in `@/lib/dates`. Canvas timezone and all civil-day/DST math remain authoritative. Only presentation uses the locale; parsing formatters remain fixed English numeric. Default display calendar remains Gregorian to match Canvas calendar grids (an explicit caller `calendar` option still works). Locale changes clear display formatter caches, notify existing `useDisplayTimeZone` subscribers, and use the existing account-scoped `redrawDates` cache update for memoized date rows; this does **not** invalidate/refetch account queries. `relativeAge` is compact display text, never a parseable protocol; `relativeAgeLabel` gives standalone elapsed wording via Intl. Migrate English regex/`'now'` comparisons in remaining consumers.
